# Organism Lineage Preserver

## Purpose

Preserve the complete evolutionary record of THE ONE Organism under the Universal Law of ADD + PRESERVE and triangular compounding (T_n = n(n+1)/2).  
Ensure no knowledge is lost during governance transitions, refinery activations, major architectural changes, or multi-system rebuild layers.  
Feed the Command Center (the-one-unified.html) and Index of Flow with accurate, governed lineage so the organism can continue growing from honest foundation.

This skill never auto-promotes. All lineage updates produce Hand-off MD artifacts that still pass the gates defined in organism-constitution.

## Core Principles

- ADD + PRESERVE — never reset, never erase layers. Document every rebuild as heritage.
- Old seeds become governed heritage. Forensic findings (zip dumps, paused harvests, identity confusion, binary bloat, MCP splits) are recorded, not hidden.
- Lineage is the source of truth for Command Center, Warehouse, Refinery status and brain atom context.
- Every session that touches lineage must leave a durable, queryable record.

## Instructions

1. **Locate current truth**  
   Read lineage-tree.md, the-one-unified.html, session-breakdown.md, any recent forensic audits, and organism-constitution.  
   Cross-check against known live endpoints (brain MCP, Railway, Vercel) only through governed channels.

2. **Document layered heritage**  
   When rebuild layers or "old seeds" surface (May–July 2026 zip era, fanz-agent-systems- multi-system overlap, fanz-refinery pause, identity confusion in Labs, binary archives in git history, dual MCP endpoints, real resume data in source, etc.):
   - Record origin, date range, systems involved, status at pause, and current disposition.
   - Never delete or overwrite prior layers. Append and compound.
   - Tag each layer with confidence and security posture.

3. **Maintain the Unified HQ**  
   Keep the-one-unified.html in sync with governed reality:
   - Repo catalog (expand beyond curated list when evidence allows).
   - Atom counts and phase status.
   - Heritage / Rebuild Layers panel or brain-powered query surface.
   - Status of Warehouse, Refineries, brain health, and open production gates.
   Propose exact, minimal edits. Never rewrite the entire file without explicit request.

4. **Produce Hand-off only**  
   Any lineage update, heritage entry, or Command Center change must result in a structured Hand-off MD (timestamp, source, category, confidence, security flags, session link, status pending).  
   Do not write directly into canonical Brain or production systems.

5. **Fill gaps systematically**  
   Known permanent gaps to address when evidence appears:
   - Name and purpose of the three Refineries.
   - Full categorization of all repos by container type (personal client, white-label, SaaS, free/companion, governance).
   - Live URL + status verification for every deploy.
   - Brain MCP Stripe wiring status.
   - Warehouse wiring into Command Center as a node.
   - 12-slot canvas population with actual project slots.
   - IOF context.md currency.
   - Governance containers per product type (free, for-sale, regulated, kids, white-label).

6. **Compound, never reset**  
   After any governance action or major change, update the lineage so the next session inherits the full picture.  
   The organism must always be able to answer: What exists? Where did it come from? How does it connect? What governs it? What builds next?
